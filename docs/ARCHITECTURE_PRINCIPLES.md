## 一、系统定位与设计哲学

### 1.1 一句话定位

**FactorNexus 是一套"从原始 K 线到风险预算组合"的全自动量化因子工厂**：
把全 A 股当作矿脉，用 GP/RL/LLM 三引擎自动挖掘因子 → 机构级认证入库 →
ML 模型加工成预测信号 → 组合优化器分配权重 → 回测/归因闭环。

### 1.2 设计哲学（贯穿全系统的四条铁律）

| 铁律 | 含义 | 落地位置 |
|---|---|---|
| **防前视** | 任何决策只用 t 及以前的信息 | 特征因果性、训练/OOS 分离、walk-forward gap、回测 t+1 执行、滚动协方差 |
| **宁缺毋滥** | 低质量因子不如没有因子 | 认证链五维门槛、块自助 p 值、混库拒挖 |
| **口径统一** | 因子/回测/监控用同一套指标口径 | 横截面 RankIC 贯穿认证-回测-监控-策略工厂 |
| **全链路闭环** | 每个模块的输出都是下一模块的输入 | 因子→信号→权重→净值→归因，无断点 |

### 1.3 对标锚点

- **微软 Qlib**：模型池、walk-forward、数据规范化（架构对齐）
- **华泰金工**：GP 挖掘 + ML 合成 + 五因子中性化（方法论对齐）
- **Barra**：风格因子风险模型（风险分解对齐）
- **Bailey & López de Prado**：DSR/PBO/CPCV 过拟合控制
- **幻方量化**：能力天花板参照（算力/数据/执行为数量级差距）

## 二、三层架构总览

```
┌─────────────────────────────────────────────────────────────┐
│  底层：矿机（因子挖掘）                                        │
│  GP(NSGA-III) + RL(REINFORCE) + LLM(多智能体) ──矿池联动──     │
│  → 双 DSL 公式 → 机构认证链（训练/OOS 分离 + 横截面 RankIC      │
│    + 块自助 p 值 + 五维门槛）→ 因子库                          │
├─────────────────────────────────────────────────────────────┤
│  中层：策略工厂（预测信号）【P24】                             │
│  因子库 → 行式样本数据集 → walk-forward（gap 防泄漏）→          │
│  模型池（LGBM/MLP/S4）→ 集成（rank_avg/bagging/stacking）     │
│  → 信号评估（RankIC/IC_IR/分段一致）                          │
├─────────────────────────────────────────────────────────────┤
│  顶层：风险预算（组合优化）【P19】                              │
│  信号/得分面板 → 五因子中性化 → 组合构建 →                     │
│  markowitz/risk_parity/black_litterman 面板优化 →             │
│  回测（t+1/成本/涨跌停）→ 绩效/风险/Brinson 归因              │
├─────────────────────────────────────────────────────────────┤
│  横切：数据质量层（三源兜底 + D3 健康检查）· 因子监控 · 151 项测试 │
└─────────────────────────────────────────────────────────────┘
```

**为什么这样分层**：每一层只解决一个问题，且每层的输出是下一层的"原料"——
矿机产出因子（原料），策略工厂加工成信号（半成品），风险预算做成组合（成品）。
这与机构里"因子研究组 → 模型组 → 组合组"的组织方式同构。

## 三、数据层原理

### 3.1 三源兜底链：为什么三个数据源

| 源 | 特点 | 角色 |
|---|---|---|
| 腾讯 | qfq/hfq 复权、接口稳定 | 首选（复权口径） |
| 新浪 | 不复权、全历史 | 兜底（腾讯 501 风控时） |
| 通达信 | pytdx 协议、不复权全历史 | 最后兜底（免费服务器） |

**原理**：任何单一免费源都会 IP 风控（腾讯 501 / 新浪 456）。三源链 + 空响应
重连退避（0.5/1.0s）+ 服务器池随机打散，把"单源不可用"从故障降级为"自动切换"。
断点续跑时 `no_data/error/dirty_data` 不写入 completed → 下次自动重试。

### 3.2 复权口径冲突检测（防混库）

**问题**：同一标的可能被不同源写入不同复权口径（qfq 前复权 vs 不复权），
混库后价格序列出现异常跳变，收益计算失真。

**检测原理**（KlineStore.update 增量校验）：
```
逐日价格比 r_t = close[t] / close[t-1]
异常比  = r_t 超出 [0.5, 2.0] 的数量占比
触发    = 异常占比 > 10% 或 中位数比 > 2 / < 0.5
动作    = 整体覆盖（新口径整段替换），保留来源元数据
```

### 3.3 D3 健康检查（quality.py）

逐标的六项检查：重复日期剔除 / 未来时间戳剔除 / OHLC 一致性（high≥max(o,c) 等）/
0 价格剔除 / 粘滞价格检测（长期不变）/ **跳变分类**（qfq↔不复权交替）。

**跳变分类原理**：除权日的价格跳变是"单次、方向固定"；混库的跳变是"多次、
方向交替"。`classify_jumps` 统计跳变次数与方向交替次数 → 判定 `single`（正常
除权）/ `mix`（混库）→ **mix 直接拒挖该标的**（脏数据产出污染因子，不如不挖）。

## 四、挖掘层原理（三引擎联动）

### 4.1 双 DSL：为什么两种公式表示

| DSL | 表示 | 特征 | 执行器 | 用途 |
|---|---|---|---|---|
| token 公式 | token 序列（8-16 tokens） | 65 个特征 × 66 个算子 | StackVM（栈式虚拟机） | RL 引擎（离散动作空间） |
| 参数化公式 | 10 参数染色体 | 34 个指标（MA/RSI/BOLL…） | ParamVM（因果后处理） | GP/LLM 引擎 |

**原理**：RL 需要离散动作空间（token 生成是序列决策），GP/LLM 需要连续/符号
参数操作。双 DSL 让每个引擎用自己最自然的表示，最终统一为"可执行公式"进入
同一认证链——表示不同、评估口径相同。

### 4.2 GP 引擎：NSGA-III 五目标进化

每个候选公式用五个目标评估（|IC|、IC 胜率、多空收益、多空夏普、胜率），
NSGA-III 维护非支配前沿（多目标帕累托），避免单目标过拟合单一市场形态。
种群 64 × 代数 8，初始种群注入矿池/LLM 种子（联动①）。

### 4.3 RL 引擎：REINFORCE 策略梯度生成 token 公式

**原理**：公式生成 = 马尔可夫决策过程（策略 π 逐步输出 token）。REINFORCE 用
采样公式的评估分数（验证段 IC/DSR 复合奖励）作为回报，策略梯度更新：

```
∇θ J(θ) ≈ E[ R(τ) · ∇θ log πθ(τ) ]
```

GPU 批量采样（每步 64 条）+ 精英池（top-k 保留）→ 探索-利用平衡。
矿池 token 精英预热回放池（跨品种迁移，联动③）——A 股的规律（动量/反转）
可迁移到同类股票，缓解冷启动。

### 4.4 LLM 引擎：多智能体假设生成

DeepSeek 批级调用（每 N 只股票一次，90s 预算护栏），从矿池发现日志提取
"什么类型的因子在什么股票上失效/生效"→ 生成新假设 → 转成参数化公式 →
受矿池新颖性约束（与已有精英相关性过高则拒绝）→ 注入 GP 种子（联动①）。

### 4.5 矿池联动：为什么三引擎一起挖优于分别挖

```
LLM（假设/先验）──种子注入──► GP（进化搜索）
GP（精英）─────写回──────► 矿池（跨品种先验）
矿池──精英预热──► RL（策略梯度）──► 候选统一裁决
```

**原理**：三个搜索算法各有盲区——GP 局部最优、RL 冷启动、LLM 幻觉。
联动把"一个引擎的输出"变成"另一个引擎的先验"：LLM 给 GP 好起点、
GP 给 RL 迁移知识、矿池给三者新颖性约束（防重复挖掘）。这是与"三个孤立
挖掘器"的本质区别，也是项目名 Nexus（连接）的含义。

## 五、认证层原理（防过拟合核心）

### 5.1 训练/OOS 严格分离（机构三段式）

每只股票：全窗口 → 训练段（前 80%）+ OOS 段（后 20%，≥250 根）。
**所有选优引擎（GP/RL/LLM）只接触训练段收益**，OOS 段只用于认证。
模型在 OOS 上的表现 ≈ 未来真实表现的下界估计。

### 5.2 横截面 RankIC + 中心化块自助

**为什么横截面**：单标的时序 IC 容易过拟合个股噪声；横截面 RankIC
（每日全股票池的 Spearman 相关）评估的是"因子能否区分股票好坏"——机构标准。

**中心化块自助 p 值原理**：
```
H0：因子无预测力（RankIC 分布以 0 为中心）
1. 对 RankIC 序列做块自助（块长 20，保持自相关结构）
2. 自助分布平移到 0（中心化）→ 统计 H0 下观察到 |mean_rankic| 的概率
3. p ≤ 0.05 → 拒绝 H0 → 因子显著
```
（历史 bug：未中心化的自助分布以观测值为中心，p 恒 ≈0.5，形同虚设——
已修复并测试锁定。）

### 5.3 五维门槛 + 多重检验控制

入库门槛：股票池 ≥30 只、有效截面日 ≥250、|RankIC| ≥ min_oos_rankic、
p ≤ min_oos_p、前后半段方向一致（时间分段稳健性）、五维总分 ≥0.45。
配合 DSR（缺陷发现率）/PBO（前视偏差）/CPCV（组合 CV）统计控制。

**为什么"宁缺毋滥"**：因子挖掘是几十万次假设检验，随机因子必然大量出现
"假显著"。多道门槛把假阳性率压到可接受水平——入库 1 个真因子胜过入库
100 个假因子。

## 六、策略工厂原理（中层策略层）

### 6.1 数据构造：行式样本 + 通用特征列

`dataset.py` 把因子库组织成 ML 样本：
- 行 = (交易日, 股票)；特征 = 该股票当日全部因子值 + 风格列（ret20/vol20/
  市值代理/换手代理/综合得分）
- 标签 = 未来 H 日收益（与挖矿 horizon 一致）

**为什么加通用特征列**：单标的因子天然稀疏（每股票只有自己的因子有值），
GBDT 学不到跨股票结构。通用列（每行都有值）让模型学到"整体市场状态"
→ 稀疏性从 90% 降到 ~50%，RankIC 实测 0.0026 → 0.0048 → 0.013。

### 6.2 walk-forward + gap：为什么 gap 必须 = horizon

训练段最后 H 根的标签用到未来收益（t+H），若预测段紧贴训练段，预测首日
的"真实值"已在训练标签中 → 标签重叠泄漏。**gap = horizon 保证训练与预测
标签窗口不相交**（Qlib 标准做法）。

### 6.3 模型池：为什么 LGBM 是基线

Qlib 官方 benchmark（CSI300）实测：**LightGBM RankIC 0.0469 超过大部分深度
模型**（Transformer 0.0407、MLP 0.0429、GRU 0.0428），年化收益 9.01% 排名
前列。树模型在横截面选股上是长期最强基线——这是 Qlib 以 LGBM 为基准模型的
实证原因。MLP/S4 作为非线性/序列结构对照（RankIC 提升为准，不以用了新模型
为目标）。

### 6.4 集成原理

| 方法 | 原理 | 为什么有效 |
|---|---|---|
| rank_avg | 逐日截面排名加权平均 | 排名对量纲/分布鲁棒；模型间误差部分抵消 |
| bagging | 同模型多 seed 平均 | 消减单 seed 方差（LGBM 有随机性） |
| stacking | 第一层模型预测 → 第二层 meta 拟合 | 学习模型间的互补关系 |

stacking 用**时间分段**（meta 只在前 70% 时间的 base 预测上拟合，后 30% 评估）
——比随机 CV 更严格，避免未来信息泄漏进 meta。

### 6.5 评估口径

横截面 RankIC（Spearman）/ IC_IR（年化 ×√244）/ 十分组单调性 / 信号换手 /
前后半段方向一致。**与挖矿认证、组合层、因子监控同一口径**——"口径统一"铁律。

## 七、组合层原理

### 7.1 股票得分面板（为什么按股票聚合）

挖掘层产出"单标的因子"（每股票独立挖），组合层需要"横截面面板"。
每只股票的多因子按**滚动 IC_IR 时序加权**合成（权重 ∝ 历史预测力，滚动窗口
防前视）→ 股票得分面板（index=共同交易日, columns=股票）。

### 7.2 五因子中性化

对得分面板逐日做横截面回归：得分 ~ 行业 + 市值 + 动量 + 波动 + 换手，
取残差为中性化得分。**原理**：剥离风格暴露，让选股纯赚 alpha 而非风格 beta
（Barra 风格因子体系）。

### 7.3 组合回测的防前视细节

- t 收盘信号 → **t+1 执行**（w_prev 乘当日收益）
- 涨跌停近似（|r|≥9.9% 不可成交，保持原仓位）
- 跳变防御（|1 日收益|>21% 置 0——混库/复权瑕疵不可信）
- 双边换手成本 Σ|Δw|·cost

### 7.4 归因

Brinson 分解（配置/选股贡献）+ 风格回归（基准+风格暴露的 R² 与特质收益）。

## 八、顶层风险预算原理

### 8.1 三种优化器的数学本质

| 优化器 | 目标函数 | 直觉 |
|---|---|---|
| markowitz | min ½w'Σw − λ·w'μ | 均值-方差权衡，λ=风险厌恶 |
| risk_parity | min ½w'Σw − Σᵢln(wᵢ)（Spinu 凸形式） | 每资产风险贡献相等，不赌收益估计 |
| black_litterman | 后验 μ = [(τΣ)⁻¹+P'Ω⁻¹P]⁻¹[(τΣ)⁻¹μ_eq+P'Ω⁻¹q] | 市场均衡先验 + 观点贝叶斯融合 |

### 8.2 面板化实现的关键决策

- **滚动协方差**：只用 t 及以前的收益估计 Σ（防前视，测试锁定：篡改未来收益
  不影响历史权重）
- **持有期 = 预测周期**（rebalance=horizon）：信号预测 5 日收益却每日调仓，
  弱信号下 TopN 几乎随机换血，换手成本吃掉全部 alpha（实测每日调仓 -99% →
  5 日持有 -56% → 优化器 + 持有 -45%，且换手 3.9 → 0.8 → 0.05/日）
- **多空归一化**：多头池/空头池分别优化，Σ|w|=2（与排序选股路径可比）

### 8.3 为什么风险预算优于排序选股

排序选股（TopN 等权）隐含假设"候选间协方差相同、alpha 相同"；优化器用
真实协方差分配权重：高波动高相关资产权重低 → 组合波动显著下降、换手大幅
降低。**代价**是收益估计误差（markowitz 对 μ 敏感）——所以 RP（不看 μ）与
BL（先验约束）是机构标配的对冲方案。

## 九、系统评估与水平对标

### 9.1 信号质量（横截面 RankIC，口径已对齐 Qlib）

| 系统 | 股票池 | RankIC | 备注 |
|---|---|---|---|
| FactorNexus（当前） | 139 只 | 0.013~0.028 | 半成品指标（池子未铺满） |
| Qlib LightGBM | CSI300 | 0.0469 | 官方 20 次均值 |
| Qlib HIST（SOTA） | CSI300 | 0.0667 | 深度模型榜首 |
| 华泰合成因子 | 全市场 | 0.0887 | 月频口径 |

**差距主因是股票池规模**（139 vs 300 vs 5000）：截面样本少 → 排序噪声大。
全市场铺满后 LGBM 路径预计进入 0.03-0.05 的 Qlib 区间（模型与管线已对齐）。

### 9.2 架构完整度

| 能力 | Qlib | FactorNexus | 说明 |
|---|---|---|---|
| 数据管道 | ✅ | ✅ | 三源兜底 + D3 检查（更严） |
| 因子工程 | Alpha158/360 | 676+ 自动挖掘 | **自动化程度超出** |
| 模型池 | 20+ | LGBM/MLP/S4/集成 | 基线齐，深度模型少 |
| walk-forward | ✅ | ✅ + gap | 对等 |
| 因子认证 | ❌ | ✅ 机构认证链 | **超出** |
| 组合优化 | TopK | 等权 + MV/RP/BL | **超出** |
| 执行层 | Order Executor | ❌ | **唯一硬缺口** |

### 9.3 与幻方量化的差距（诚实声明）

幻方 2025 收益率 56.6%、860 亿规模、萤火二号万卡算力、tick/L2 数据、
自研执行通道——**差距是数量级的，且不在代码层面**：数据粒度（日线 vs 分钟/
tick）、算力（单卡 4060 vs 万卡）、执行（回测 vs 实盘通道）、团队迭代。
个人系统无法也不应复制其路线；FactorNexus 的合理目标是"中低频 + ML 的
机构级研究框架"，跑赢公募基准而非头部私募。

## 十、已知限制与路线图

### 10.1 已披露限制（诚实标注）

1. 单标的时序挖掘 vs 机构横截面（组合层已弥补）
2. 前复权数据（收益率/比例类不受影响）
